# Supabase Database Setup for Harin Learning

Copy and paste the following SQL into your Supabase SQL Editor to set up the database tables.

## 1. Profiles Table
Stores additional user information linked to Supabase Auth.

```sql
create table profiles (
  id uuid references auth.users on delete cascade primary key,
  full_name text,
  username text unique,
  avatar_url text,
  updated_at timestamp with time zone default timezone('utc'::text, now())
);

-- Set up Row Level Security (RLS)
alter table profiles enable row level security;

create policy "Public profiles are viewable by everyone."
  on profiles for select
  using ( true );

create policy "Users can insert their own profile."
  on profiles for insert
  with check ( auth.uid() = id );

create policy "Users can update own profile."
  on profiles for update
  using ( auth.uid() = id );
```

## 2. Courses Table
Stores information about courses.

```sql
create table courses (
  id bigint generated by default as identity primary key,
  title text not null,
  instructor text not null,
  price decimal not null,
  image_url text,
  category text,
  description text,
  created_at timestamp with time zone default timezone('utc'::text, now())
);

alter table courses enable row level security;

create policy "Courses are viewable by everyone."
  on courses for select
  using ( true );
```

## 3. Enrolled Courses Table
Track which users have purchased which courses.

```sql
create table enrollments (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users on delete cascade not null,
  course_id bigint references courses on delete cascade not null,
  progress int default 0,
  enrolled_at timestamp with time zone default timezone('utc'::text, now()),
  unique(user_id, course_id)
);

alter table enrollments enable row level security;

create policy "Users can view their own enrollments."
  on enrollments for select
  using ( auth.uid() = user_id );
```

## 6. Posts Table
Stores blog posts created by users.

```sql
create table posts (
  id bigint generated by default as identity primary key,
  title text not null,
  content text not null,
  category text,
  image_url text,
  author_id uuid references auth.users on delete cascade not null,
  created_at timestamp with time zone default timezone('utc'::text, now()),
  updated_at timestamp with time zone default timezone('utc'::text, now())
);

-- Set up Row Level Security (RLS)
alter table posts enable row level security;

create policy "Posts are viewable by everyone."
  on posts for select
  using ( true );

create policy "Users can insert their own posts."
  on posts for insert
  with check ( auth.uid() = author_id );
```

## 8. Migration: Update Existing Tables

Run these if you already created the tables above and need to add missing columns:

```sql
-- Add missing columns to profiles (safe to run even if columns already exist)
alter table profiles add column if not exists username text unique;
alter table profiles add column if not exists avatar_url text;
alter table profiles add column if not exists role text default 'student';

-- Add views column to posts (for Blog popularity sorting)
alter table posts add column if not exists views integer default 0;

-- 1. Izinkan INSERT (untuk pendaftaran pertama kali)
create policy "Allow insert for own profile"
  on profiles for insert
  with check ( auth.uid() = id );

-- 2. Izinkan UPDATE (untuk fitur simpan di Settings)
create policy "Allow update for own profile"
  on profiles for update
  using ( auth.uid() = id )
  with check ( auth.uid() = id );
```

> **Note:** The upsert policy syntax above is for illustration. In practice, Supabase handles
> upserts via the `upsert()` client method as long as INSERT + UPDATE policies are both set.

## 9. Storage Setup (PENTING)

Fitur unggah foto profil memerlukan bucket storage bernama **"avatars"**.

### Langkah-langkah:
1. Pergi ke **Storage** di Dashboard Supabase.
2. Klik **New Bucket**.
3. Beri nama: `avatars`.
4. **PENTING:** Centang opsi **"Public bucket"** (agar foto bisa diakses lewat URL).
5. Klik **Save**.

### SQL untuk Policy Storage:
Jalankan SQL ini di **SQL Editor** Supabase untuk mengizinkan user mengunggah foto mereka sendiri:

```sql
-- Izinkan akses publik untuk melihat foto
create policy "Avatar Public Access"
  on storage.objects for select
  using ( bucket_id = 'avatars' );

-- Izinkan user yang login untuk mengunggah foto ke folder mereka sendiri
create policy "Users can upload their own avatar"
  on storage.objects for insert
  with check (
    bucket_id = 'avatars' AND
    auth.uid()::text = (storage.foldername(name))[1]
  );

-- Izinkan user menghapus/update foto mereka sendiri
create policy "Users can update/delete their own avatar"
  on storage.objects for all
  using (
    bucket_id = 'avatars' AND
    auth.uid()::text = (storage.foldername(name))[1]
  );
```

```sql
  title text not null,

);

-- 2. Tabel Junction (Badge yang sudah dimiliki user)

alter table achievements enable row level security;
alter table user_achievements enable row level security;
```

## 11. Notification System

Tabel untuk menyimpan notifikasi sistem dan personal.

```sql
create table notifications (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users on delete cascade, -- Jika null, berarti notifikasi GLOBAL
  title text not null,
  content text not null,
  type text check (type in ('course', 'blog', 'system', 'achievement')),
  link_to text,
  is_read boolean default false,
  created_at timestamp with time zone default now()
);

alter table notifications enable row level security;

-- Users bisa melihat notifikasi miliknya sendiri ATAU notifikasi GLOBAL (user_id is null)
create policy "Users can view own or global notifications"
  on notifications for select
  using ( auth.uid() = user_id or user_id is null );

-- Sementara izinkan siapa saja (atau teacher) untuk insert notifikasi (untuk testing/demo)
create policy "Anyone can insert notifications"
  on notifications for insert
  with check ( true );
```

## 12. Individual Notification Tracking

Tabel untuk melacak notifikasi mana yang sudah dibaca oleh user tertentu (terutama untuk notifikasi Global).

```sql
create table notification_reads (
  user_id uuid references auth.users on delete cascade not null,
  notification_id bigint references notifications on delete cascade not null,
  primary key (user_id, notification_id)
);

alter table notification_reads enable row level security;

create policy "Users can manage their own read status"
  on notification_reads for all
  using ( auth.uid() = user_id );
```
